# Учебные игры для новых УМК Босовой

На сайте `/games/` опубликованы шесть игр для 6–11 классов, по восемь миссий.
Это первый набор по отдельным темам, не покрытие каждого параграфа курса.
Игры используют только локальные JS/CSS, без рекламы, аккаунтов и внешних CDN.
Ответы открыты в браузере: не применять как защищённую проверочную работу.

## Как создавать новые

Прочитай CLAUDE.md, AUTHORING.md, BOSOVA.md. Сверь выбранные темы с авторским
сайтом и reference/bosova-topics.json. Возьми `templates/game.json` как структуру,
не публикуй образец и не копируй чужие полные тексты учебника.

Составь собственный сюжет и 4–20 миссий. Для каждой обязательны id, title,
prompt, hint, explanation и topicId. Не называй викторину разнообразной игрой,
если все миссии — один выбор ответа. В игре желательны минимум три механики.
Не добавляй таймер наказания, персональные рейтинги и отправку оценок.

Типы миссий:

- single: options 2–6; answer — индекс 0-based.
- multi: options; answer — уникальные индексы всех подходящих карточек.
- number: answer — конечное число; unit — подпись поля. Комма поддерживается.
- sort: groups 2–5, items 3–10; answer — индекс группы для каждого элемента.
- order: items 3–8; answer — перестановка индексов в верном порядке.
- binary: bits 2–8; answer — десятичное значение, которое надо собрать переключателями.
- truth: operation and/or/xor/not; answer — строковые результаты как числа
  для входов 00,01,10,11 (для not: 0,1). Издатель проверяет вычисления.
- pixel: answer — 3–8 строк 0/1, прямоугольная карта шириной 3–8 клеток.
- robot: size 3–7, start/goal [x,y], walls [[x,y],...], maxMoves 1–30.
  Координаты с нуля, x вправо, y вниз. Издатель проверяет достижимость цели.

Дополнительные поля миссии: code — обычный текст, НЕ исполняемый код;
table — строки таблицы 2–12×2–6, все ячейки строковые; unit — подпись числа.

## Метаданные и публикация

kind=game. Общие поля паспорта как в AUTHORING.md; story — 1–5 абзацев,
missions — массив. Для curriculum разрешено дополнительное topicIds:
массив уникальных ID тем одной серии/класса, включающий основной topicId.
Каждый mission.topicId должен входить в него. topicLabels — словарь
читаемых подписей; его наполняй точными названиями из справочника.

Собери `python tools/publish.py drafts/SLUG.json`. Пройди все миссии в
изолированном браузере, проверь неверные/пустые ответы, подсказки, повтор,
маленький экран, клавиатуру, сохранение при обновлении и нового игрока.
Числа пересчитай отдельно; программы проследи без выполнения непроверенного кода.
Публикуй только по запросу учителя: `... --publish`.

Карточка пока использует category practice ради совместимости каталога,
typeLabel=Учебная игра и game=true. В Босовой игра появится у всех topicIds.
Ручное изменение главной/каталога не требуется. Проверяй HTTP200 и карточку.

## Проведение урока

20–30 минут в одиночку или парами. В парах меняйте оператора после миссии.
В конце ученики объясняют одно решение своими словами. Три звезды — решение
с первой попытки без подсказки; помощь/повторы снижают звёзды до минимума один,
но не блокируют обучение. Прогресс только sessionStorage данной вкладки,
до её закрытия и максимум 24 часа. Перед передачей компьютера — «Новый игрок».
Сервис не хранит имён и не отправляет оценки. Школьный журнал не затрагивается.

## Игровой тренажёр с отметкой (kind=trainer)

`/courses/trainer-{6..11}-kodograd/` — «Кодоград»: по четыре мира на класс.
В отличие от игр выше, тренажёр ведёт профиль ученика и отправляет отметку.
Движок лежит в `tools/trainer/` (trainer.js, trainer.css) и копируется издателем
в папку задания; общие файлы `/portal/` не меняются. После правки движка каждое
задание обновляется отдельно: `publish.py drafts/SLUG.json --publish --replace`
(только по просьбе учителя).

JSON: общий паспорт, `story`, `grading` (three/four/five, % звёзд мира),
необязательный `classLetters`, `worlds` 1–12. Мир: id, title, description,
type, `lang` py/ru, необязательный topicId из curriculum.topicIds, levels 3–10.
Уровень: id, title, prompt, hint, explanation и поля механики:

- robot: grid (строки из `# . S G *`), dir N/E/S/W, blocks (forward, left, right,
  repeat, while, if), conds (free, wall, left, right, notgoal), par — блоков на
  три звезды, max — предел, solution — эталонная программа (только в ключе).
- trace: w, h, start, program (move/repeat/for/set/if/while/call), funcs.
  Выражения — число, имя переменной или [операция, a, b].
- binary: mode dec2bin/bin2dec/base2bin/bin2base/sum, bits, count, min, max,
  base 8/16, weights, readout. Числа случайные.
- calc: count и tasks: text с {переменными}, vars — списки значений,
  answer — выражение, unit, tip. Ответ обязан быть ровно целым при любых значениях.
  Имена переменных — латиницей, промежуточные значения не больше 2⁵³ (точность браузера).
- logic: inputs, nodes (id, in, необязательные gate и row), target, gates1, gates2.
- pixel: rows из 0/1, show bin/hex/dec, weights.
- graph: nodes (id, x, y в процентах), edges [a, b, длина], from, to.
- draw: w, h, start, dir, blocks (forward, left, right, repeat), par, max,
  solution. Образец рисунка издатель строит сам по solution.
- filter: nameLabel, fields (имена полей строчными), rows [подпись, числа…],
  cond — выражение над полями; ученик отмечает строки, где оно истинно.
- sort: values (4–8 разных чисел), order asc/desc; обмены только соседних.
- cipher: mode decode/encode/crack, word (заглавные русские буквы без Ё), shift.
- truth: vars (A, B, C), cols — выражения-столбцы слева направо; операции
  and, or, not, -> (импликация), <-> (эквивалентность).
- array: init {a: [числа]}, program (как в trace, плюс seta и выражение
  ["at", "a", индекс]), ask — имя переменной или массива для ответа.
- sheet: cols, rows, cells: число, {"t": текст} или {"f": формула}; функции
  sum/avg/min/max/count по диапазону, ["if", условие, a, b], ссылки с $.
- path: tree {name, children}, ask click/type, target — путь списком имён.

Аркады (с 09.10.2026): binary — «Двоичный конвейер», calc — «Защита сервера»,
filter и truth — «Турникет», sheet — «Зависшие формулы». В них таймер и три
жизни (у конвейера — переполнение), звёзды зависят от потерь. Темп задаётся
необязательными полями уровня seconds и gap (секунды). truth использует
последнее выражение из cols. Игра начинается только по кнопке «Старт».

- pairs («Мемори»): pairs — 4–8 пар строк, все тексты разные.
- hunt («Тир по массиву»): a — массив, queries — [задание, индекс], showIndex,

## Игра на Godot «Мастерская роботов» (12.10.2026)

Пробная игра на движке Godot 4.7: `/courses/game-6-robot-workshop/`, проект `godot/workshop/` (GDScript: `levels.gd` — уровни, `sim.gd` — исполнитель без графики, `board.gd` — поле, `main.gd` — меню и редактор блоков). Ученик собирает роботу-погрузчику программу из блоков (вперёд, повороты, взять, положить, повтори, если — иначе, пока); звёзды за работающую и короткую программу. В уровнях со случайными цветами программу проверяют три смены. Прогресс — в localStorage браузера, в журнал ничего не отправляется.

Godot стоит в домашней папке (`~/.local/opt/godot`, команда `godot`), веб-шаблоны без потоков — в `~/.local/share/godot/export_templates/4.7.2.stable`. Сайт работает по http, поэтому годится только экспорт без потоков (`variant/thread_support=false`).

Сборка и публикация: `godot/workshop/build.sh` (проверяет эталонные решения всех уровней и собирает `export/`), затем `python tools/publish.py drafts/game-6-robot-workshop.json` (`gameMode: godot`, `godotProject: workshop` — издатель кладёт экспорт в `game/` и делает страницу с рамкой). Проверка в браузере: `bash tools/trainer/tests/start.sh && node tools/trainer/tests/workshop.test.mjs` — проходит все уровни клавиатурой. Новый уровень добавляется в `levels.gd` вместе с эталонным решением в `tests/solutions.gd`.

Важно: стандартный загрузчик Godot отказывается работать по http («Secure Context»). `build.sh` после экспорта снимает эту проверку и пропускает звуковые ворклеты, недоступные без https.
