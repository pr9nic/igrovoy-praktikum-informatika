# Как делать качественные задания

Все файлы UTF-8. JSON — данные, не HTML: `<script>`, onclick и произвольная
разметка не нужны. Издатель экранирует текст; формулы и примеры пиши обычным
текстом. Библиотеки и шрифты не загружаются из интернета.

## Паспорт материала

`schemaVersion`: 1; `slug`: латиница/цифры/дефисы, например
`inf-8-binary-2026-10-07`; `kind`: test/practice/lesson/game; `grade`: 6–11;
`subject`: Информатика/Математика и т.д.; `title`, `description`, `durationMinutes`;
`goals`: 1–5 измеримых целей; `theory`: краткие объяснения;
`instructions`: что делать и в каком порядке. В title не нужно дублировать класс.

Тема без заданного класса: спроси класс, если это существенно меняет содержание.
Если учебник неизвестен, не выдумывай номер параграфа и соответствие ФГОС.
Время — рекомендация, не таймер принудительной отправки.

## Тест

`questions`: 3–40 вопросов. Для каждого `id` уникальный; `type`:

- single: `options` 2–6 строк и `answer` — индекс правильного, начиная с 0.
- multi: options и answer — массив уникальных индексов; зачёт только при
  точном совпадении набора, порядок выбора не важен.
- number: answer — конечное число; `tolerance` ≥0 (по умолчанию 0).
  Запятая в ответе ученика допускается. Не пиши единицы в поле ответа.
- text: answer — строка или массив допустимых строк; регистр, пробелы по краям,
  повторные пробелы и е/ё не различаются; другие формы перечисли явно.

Также `prompt`, `points` (1–10) и `explanation`: почему ответ верен.
`grading`: проценты `three`, `four`, `five`, строго возрастающие 0–100.
Порог считается по сумме баллов, а не округлённому проценту.
Не штрафовать автоматически за вторую попытку. Если нужна проверка знания,
составить новую равноценную версию; режим шаблона — обычная учебная проверка.

Указывай в вопросе систему счисления и единицы, проверяй все дистракторы.
Вопрос должен иметь однозначный ответ. Объяснение — короткое и понятное.
Разбор появляется после завершения; результаты уходят в `/results/api/submit`
с квитанцией и безопасной повторной отправкой. Ответы остаются в JS браузера:
для контрольной с противодействием списыванию нужен отдельный серверный режим.

## Практика и план урока

`steps`: 2–20 объектов `title`, `text`, опционально `example`.
`deliverable`: что именно сдавать и как назвать файл. Для practice обязателен.
`rubric`: 2–12 объектов `criterion`, `points`; баллы целые 1–20.
`reflection`: 1–5 вопросов самопроверки.
`teacherNotes`: подсказки/решение/типичные ошибки (только в teacher_key.html).
`attachments`: необязательные объекты `file` (относительно JSON), `label`.
Только реальные PDF/DOCX/XLSX/ODS/PPTX/TXT/CSV/PY/SQL/ZIP и изображения.
Файлы внутри drafts/, без symlink и выхода ../ за рабочий проект.
Не добавляй исполняемые бинарники, архивы с секретами, готовые работы детей.
Формулы в CSV, если нужны в учебном шаблоне, объясни явно; не брать случайный
CSV с персональными данными. Для Excel проверь формулы и русскую локализацию.

Практика: теория 5–7 минут, рабочие шаги 20–25 минут, проверка 5 минут.
План lesson может быть конспектом без сдачи; рубрика тогда необязательна.
Для самостоятельной работы дай исходные данные и критерии проверки.
Страница содержит кнопку «Сдать работу» с уже выбранным названием задания.

## Публикация

```
python tools/publish.py drafts/inf-8-binary.json
python tools/publish.py drafts/inf-8-binary.json --publish
```

Без --publish получишь `build/SLUG/`: index.html, безопасные assets,
опциональный teacher_key.html и item.json (карточка). В браузере preview
использует общие файлы живого сайта только для чтения; сборка не переносит
ответы учителя в каталог. Preview для статического просмотра можно запустить:
`python tools/preview.py` → http://127.0.0.1:18719/courses/SLUG/.
На preview отправка оценок выключена: кнопка покажет демонстрационное сообщение.

--publish добавляет только новый courses/SLUG и карточку, без рестартов сервисов.
Повторная публикация существующего slug запрещена; намеренное обновление
делается --replace после проверки и разрешения пользователя.
Резервная копия: backups/дата-время-случайныйID (не раздаётся через веб).
При ошибке до изменения каталога папка может остаться без карточки — проверь
отчёт, не удаляй другой материал. При неопределённой ошибке сначала прочитай
live index/catalog; не повторяй публикацию вслепую.

## Проверки перед отчётом

Содержание: ответы самостоятельно решены, суммы и шкала корректны,
нет заглушек/противоречий, теория помогает, но не сообщает прямо ответы теста.
Техника: все скачивания открываются, mobile390 не разъезжается, клавиатура
работает, пустой ответ не принят, успех не показывается при ошибке сервера.
Права: teacher_key.html с ученического IP получает 403; учитель видит ключ.
После публикации: ссылка HTTP 200, карточка появилась в нужном классе.

Шаблоны — структура и небольшие проверенные образцы. Для нового урока перепиши
все содержательные поля, не меняя протокол API и общий дизайн.

## Связь с темами Босовой

Для уроков учителя по новым УМК читай `docs/BOSOVA.md` и
`reference/bosova-topics.json`. Разрешено читать официальный сайт Босовой
для сверки содержания. Добавь `curriculum` из справочника: `provider`,
`seriesId`, `topicId`, `sourceUrl`. Издатель проверяет тему и класс,
помещает привязку в каталог; урок появляется рядом с параграфом в `/bosova/`.
Для других предметов это поле можно не указывать.

## Учебные игры

`kind: game`, шаблон `templates/game.json`, правила `docs/GAMES.md`.
Игры создают игровые миссии и звёзды, но не отправляют школьные оценки.
`curriculum.topicIds` связывает игру с несколькими темами одной серии.
